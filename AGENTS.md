## Code conventions
- Public functions set state; logic runs in `FixedUpdate`/`Update`. Multi-value setters (e.g. `RotateRight()` sets direction + speed) live in the frame loop.
- Single responsibility per script:
  - `PlayerControl` — Input proxy. Reads keyboard, calls 3 commands on `PlayerBehaviour`. Never touches animation or kit.
  - `PlayerBehaviour` — Physics + state holder. Owns kit, exposes direction/speed for animation, applies rotation in `FixedUpdate`.
  - `PlayerKit` — Kit state + countdown timer. MonoBehaviour with its own `FixedUpdate` for timer. Exposes `GetKit()` and `ApplyKit()` only.
  - `PlayerAnimation` — Animator driver. Reads behaviour state + kit in `FixedUpdate`, sets Animator speed and state. Does not set kit.
- `PlayerControl.cs:13` polls `Keyboard.current` directly; does not wire through `InputSystem_Actions.inputactions`. Agent adding InputActions must also wire `PlayerControl`.
- `PlayerAnimation.cs:25` hardcodes `No_kit_{left/right}` states; new `KitType` entries need corresponding animation state names and mapping.
- `PlayerKit.cs:32` decrements timer via `timer -= Time.fixedDeltaTime` inside `FixedUpdate` — note timer logic is in `FixedUpdate`, not `Update`.
- Enums for state: `PlayerDirection`, `KitType` instead of magic strings/ints.
- No direct input in Behaviour: Only `PlayerControl` reads input. `PlayerBehaviour` is input-agnostic.
- No abbreviations in variable/parameter names: Write `keyboard`, not `kb`. Write `behaviour`, not `bhv`.
- `Debug.Log` in `PlayerBehaviour.cs:FixedUpdate` (lines 44,51) — avoid in shipped builds; performance trap.
- `Animator.speed` cannot be negative at runtime. Only works in recorder mode. For reverse animation, duplicate states with `-1` speed in the Inspector or use `animator.Play(stateName, 0, normalizedTime)`.
- Animation clips use `_left`/`_right` suffixes (e.g. `No_kit_left`, `No_kit_right`). State names must match exactly when calling `animator.Play()`.
